# Term Linking Convention (DRY / anti-drift rule)

Status: Draft
Ratified: No
Last updated: 2026-09-22

Applies to every layer's Definitions (and later, Taxonomy/Ontology) files
across the whole framework.

## Rule

A term is written exactly once, in its owner layer's definitions file.
No other file ever copies its text. Anything elsewhere that needs the term
holds a link, never a duplicate definition.

## Mechanics

1. **Stable ID** — every term gets a slug of the form `<layer-prefix>-<kebab-case-term>`,
   e.g. `infra-gpu-memory`. IDs are permanent even if display wording changes.

2. **Anchor heading** — the term is defined once, under a heading carrying
   its ID as an anchor:
   ```markdown
   ### GPU Memory (VRAM) {#infra-gpu-memory}
   Dedicated high-bandwidth memory on a GPU...
   Source: Common industry practice
   Referenced by: System Architecture, Harness
   ```

3. **Reference stub** — a layer that needs a term it doesn't own adds a
   pointer, never a redefinition, typically in a "Referenced Terms (owned
   elsewhere)" section of its own Definitions file:
   ```markdown
   - **GPU Memory (VRAM)** — owned by Infrastructure →
     [01-infrastructure/01-definitions.md#infra-gpu-memory](../01-infrastructure/01-definitions.md#infra-gpu-memory)
   ```

4. **Reverse tag** — the owner's own entry carries a `Referenced by:` line
   naming which other layers point to it, kept in sync manually for now
   (candidate for automation once a generation script exists).

5. **Unified glossary** — `00-framework/glossary-master.md` is generated by
   scanning every layer's Definitions file for `{#id}` anchors and compiling
   one index of links back to each term's single owning file. It never
   contains copied definition text.

## Layer prefixes

| Layer | Prefix |
|---|---|
| Infrastructure | `infra` |
| Networking | `net` |
| System Architecture | `sysarch` |
| Data/Metadata | `data` |
| Workflow/Process | `wf` |
| Harness | `harness` |
| Interface/Human | `iface` |

## Inheritance (`extends`) — for genuine specialization, not homonyms

Reference stubs (above) handle *same word, unrelated meanings* across
layers — e.g. two terms that happen to share a name but describe different
things, kept fully independent under different IDs.

Inheritance is a different, narrower relationship: *same underlying
concept, one layer narrows or adds detail to it*. Use `extends` only when
the child's meaning would never contradict the parent — if it would, it's
not a specialization, it's an independent term (use a reference stub or a
standalone definition instead).

### Rules

1. **One level only.** A term may extend exactly one parent. No chains
   (`A extends B extends C`). Keeps resolution simple and matches the
   quality bar (00-framework/quality-bar.md).
2. **The child writes only the delta** — what it adds or narrows — never
   a restatement of the parent's full text.
3. **Format:**
   ```markdown
   ### Infrastructure Risk {#infra-risk}
   Extends: governance-risk
   Adds: risk specifically arising from hardware failure, capacity
   exhaustion, or facility-level disruption.
   Source: Org convention, building on NIST SP 800-53 (RA family)
   ```

## Authoring format vs. AI-consumption format

The source files (as described above) are optimized for humans
maintaining the framework: DRY, no duplication, no drift, one place to
edit. That is the right shape for authoring, but it is not the right
shape to hand an AI/harness at runtime — resolving `extends` and
`Referenced by` links correctly, every time, across every query, is a
multi-hop task an AI can get wrong silently (a missed hop reads as a
confident but incomplete answer).

**Rule:** a second, generated artifact —
`00-framework/ai-resolved-glossary.md` — holds the fully flattened,
self-contained version of every term: parent text merged with every
child's delta, in one place, with a provenance note on which part came
from where. This is the artifact an AI/harness/retrieval system should
actually be pointed at, never the raw source files with unresolved links.

Same principle as `glossary-master.md` (generated, never hand-edited) —
this is the AI-consumption-optimized sibling of that index. Not built yet;
build it the first time a real `extends` case exists to resolve.
